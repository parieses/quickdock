01Install

Download quickdock-amd64-installer.exe and run it. No admin rights at any point.

  • It installs to %LOCALAPPDATA%\Programs\快启坞. Afterwards run QuickDock.exe; a tray icon means it's up.
  • Keep the default install path. Auto-update depends on write access to that directory. Put it in C:\Program Files and every update has to clear UAC, which leaves you overwriting by hand.
  • Installing is optional: grab quickdock-amd64.exe and run it as a portable build from a directory your user can write to. In-place updates work there too.
  • The first launch asks once where to keep data. To change it later, go to Settings → Storage & Sync.

02Interface

A sidebar on the left, one page on the right. Every page carries a full-width header: title on the left, actions on the right.

  • Header: 46px tall, 15px title. At most one solid blue button on the right — it is reserved for what that page is mostly for. The rest are outlined or icon-only, set off from the primary by a short vertical rule.
  • Sidebar: top to bottom runs the navigation — dashboard, workspaces, notes, todos, scheduled tasks, script tasks, site monitors, clipboard, file search, knowledge base, bookmarks, runtimes, downloader, netdisk, Git, password vault, SSH, AI, DeepSeek Harness, plugins. Right-click any entry to hide it or move it up and down; hidden ones collect in a Hidden group below and can be brought back at any time. Hiding only trims the sidebar — CtrlK still finds the page. The bottom row is fixed: notifications, settings, collapse. Collapsed, the sidebar is icons only.
  • Switching pages: the old page fades out before the new one fades in, so the content area is briefly empty — that is the transition, not a failure. Dashboard, notes, todos, scripts and plugins stay alive after you leave: coming back shows the previous content right away and refreshes quietly in the background, with no white reload.
  • Workspace: three panes — scenarios, collections, items — each with its own search row and empty state. With no collection selected the right pane shows a hint; that is expected.
  • Dashboard: the home page. A date bar on top carries the lunar date, solar terms, the day's traditional do's and don'ts and local weather (turn it off from the gear; the lunar calendar and almanac are computed offline). Below sit the readouts and cards: upcoming schedules, recent items, the file shelf, today's todos, script tasks, mail verification codes, ports, resident services, Git state, site health and AI usage. An abnormal readout turns red and pulses faintly; clicking any row lands on that page with the item selected.
  • Settings reopens on the page you left it on; the very first open lands on General. Switching pages inside the panel only swaps the right side — there are no second-level pages.
  • The interface scales proportionally under Settings → General. The main window and every detached window zoom together and the proportions stay put.
  • The same page picks the window material (Mica, Acrylic or Mica Alt); restart to apply. The main window, the four floating panels, SSH and plugin windows all share one setting. On Windows 10, with system transparency off, or in high contrast, it falls back to solid colours — that is expected.

03Hotkeys

Eight global hotkeys by default. These are the ones you'll reach for all day.

  • CtrlSpace show or hide the main window
  • CtrlK command palette
  • Ctrl` clipboard history
  • CtrlAltN quick notes
  • F1 region screenshot, falling back to CtrlShiftA when it's taken
  • CtrlAltW window tiling overlay, plus 15 more snap hotkeys under Settings → Window Management
  • CtrlAltS SSH terminal
  • CtrlAltL lock the UI (set a startup password under Settings → Security first)
  • All of them can be rebound under Settings → Hotkey Settings, effective immediately, no restart. If you forget one, type cheatsheet in the command palette; the sheet reads your current bindings.

04Resources

Four levels: workspaces hold scenarios, scenarios hold collections, collections hold items.

  • Workspaces are the outermost container: the first launch creates one and every scenario hangs under it. A deleted workspace can be restored from Settings → Recycle bin.
  • Scenarios are slices of the same resources, with their own tags, icons and colors. Switch to Frontend while writing code, Production while on call.
  • Collections group by purpose and carry one of four open strategies, which decide whether items open all at once or one by one.
  • Items come in six types: folder, file, URL, terminal command, application, shortcut with arguments.
  • Every level can be dragged into order. Commands and URLs accept {date}, {time}, {username} and {clipboard}, expanded at the moment they open.
  • Items can be ticked for batch delete or moved to another collection in the same scenario. An item can carry a mark colour and a custom icon (an image up to 256 KB), plus its own extra arguments.
  • When you can't find something, CtrlK beats digging through the tree.

05Command palette

CtrlK opens it. Type to search, press Enter to run.

  • Results are grouped by source: best match, recent, projects, scenes, workspace collections, quick links, notes, todos, applications, files, plugin commands, runtime services, system commands, clipboard suggestions, plus inline calculator and web results. Scenes and collections open the workspace page at that exact item. Typing a page name brings up Quick navigation — bookmarks, downloads, netdrive, credentials, scripts and the rest all jump straight there; Git repos and SSH hosts have their own groups, and picking a host wakes the SSH window already connected.
  • Type "new note" or "new todo" to create one inline: type a title, press Enter, and the new entry opens right away.
  • Todos only return unfinished top-level tasks. Enter switches to the todo page, jumps to that day, clears tag filters when needed and highlights the row for two seconds; the action menu can mark it done.
  • Type an expression and the answer appears; paste a URL and it asks whether to save it as a project.
  • Type cheatsheet for the hotkey sheet, or logtail to open log tailing.
  • When there are too many files to skim in the panel, the sidebar's File search page is a dedicated view backed by Everything: install guidance when it is missing, one-click start when it is not running, index progress while it builds. The query box takes Everything syntax directly (with a hint inside the page), results sort by name, path, size or time, selecting many lets you copy all paths at once, and the right side previews the file. The page offers no delete action.
  • Two boundaries worth knowing: clipboard history entries aren't searched (the suggestions only cover what you just copied), and each group has a display cap — only recent can be expanded.

06Clipboard

Ctrl` opens the float window, which hides as soon as it loses focus.

  • Text, images and files are all recorded. Images live in ~/.quickdock/images/.
  • Tags come in two kinds: Images, Files, All and Starred filter by type; URL, Email, Phone, JSON and Code are smart categories that only apply to text.
  • Classification is computed and stored when an entry is written, so picking a tag reaches the whole history rather than the 1000 rows the All list loads by default.
  • Search runs against the whole database, not just the 1000 rows the list shows; type filters are pushed into the same query.
  • An entry can be pasted as plain text, Markdown text or pretty-printed JSON. Several entries can be queued and pasted in sequence, with skip and clear controls.
  • Under Settings → Clipboard you can ignore specific source windows, or pause capture for a number of minutes until you resume it. This affects what gets recorded, not what is stored.
  • Ask AI on an entry to translate, summarize or reformat — or ask your own question — answered in place, without leaving the page.
  • Retention is set under Settings → Clipboard, and entries expire on schedule. Automatic rules can clean up what you copy, with a dry run first.
  • History can be cleared in one go, file entries reveal in Explorer, and images save to disk. Rules can be ordered by priority, and you can simulate a source window to see whether they'd match.
  • Every copy in the app goes through the backend system API, unaffected by which window has focus.

07Screenshots

F1 raises a full-screen overlay. Draw a selection and the toolbar appears in place.

  • Six annotation tools: rectangle, ellipse, arrow, line, mosaic, text. Nine colors, four stroke widths, six text sizes.
  • While selecting, hovering a window highlights the whole window and one click takes it; hold Ctrl to drop to the child control.
  • Annotations can be selected, dragged and deleted, text can be double-clicked to edit, and the selection has eight handles.
  • Pin a capture to the screen afterwards: drag it, scroll to scale, double-click to close, or rotate / flip it and let mouse clicks pass through (Esc releases it).
  • A color picker reads the pixel under the cursor and copies its value; numbered markers use "largest existing number + 1", so undo or delete never leaves a gap.
  • Text annotations are WYSIWYG: what you type is drawn at the anchor instead of jumping back from a side input.
  • Common keys: Enter or CtrlC copies, CtrlS saves, CtrlZ undoes, REALMT switch tools, Esc steps back out.

08Notes

CtrlAltN opens the floating notes window.

  • A tree of notes on the left, folders nest, with search, rename and delete. Write [[Note title]], [[todo:...]] or [[item:...]] in the body to link across notes, todos and items; the preview follows the link, and a backlinks panel shows who links here.
  • Content is stored as Markdown and saved 500 ms after you stop typing. There is no save button.
  • The window hides when it loses focus, so it never sits on top of your work.
  • Ask AI in the float: with a selection only that goes, without one the whole note. Presets cover summarize, polish, continue and translate, and you can ask anything. None of it is written to the AI conversation history.
  • The footer counts words, characters and lines, headings become a table of contents you can click through, the tree can be dragged into order, and the whole note exports to .md. An AI answer can go in at the cursor, onto the end, or replace the note.

09Todos

Open Todos from the sidebar; list and kanban views switch freely.

  • Tasks can carry subtasks, tags, notes and an estimate.
  • Repeat rules cover daily, weekly and monthly; finishing one creates the next.
  • A due time triggers a system notification.
  • Pomodoro runs a countdown on the todo page and notifies when it ends; a webhook can push it to your phone under Settings → Robot Notifications, where extra channels (Bark, Discord, Slack, Ntfy, Gotify and a generic JSON webhook) can be added alongside the six built-in bots.
  • Subtasks can be renamed, moved up or down, and given their own due date; the in-page search filters by title and notes.
  • Search a task title in the command palette and Enter jumps straight to it.

10Monitors

Create one under Site Monitor in the sidebar: pick a probe type, fill in the target and an interval.

  • Six probe types: HTTP (status code / keyword / regex), TCP port (a connect means up — databases, Redis, MQ), DNS (A:/AAAA:/MX:/CNAME: prefixes), Ping (system ping, no raw sockets), local process (present means up), and custom command (exit code 0 means up).
  • HTTP monitors show status code, response time and days left on the SSL certificate. Latency jitter isn't an outage; adjust the threshold in settings so a network hiccup doesn't page you.
  • A state flip pushes a desktop notification, or DingTalk, WeCom, Feishu, ServerChan, PushPlus or Telegram.
  • Trend charts cover 24 hours, 7 days and all time; the monitor list exports to CSV. The 24h p95 / p99 response-time percentiles are shown per monitor. Current average latency is compared against the 24h average (slower is flagged), each response bar fills against the timeout threshold, and a failed probe raises a banner above the card. A second tab, Status, gives a read-only overview with an exportable single-file HTML snapshot; it refreshes every 60 seconds and never opens a server port.
  • Every notification also lands in the bell at the bottom of the sidebar; the bell can filter by kind and search, and clicking a notification jumps to the exact monitor, scheduled task, todo or AI conversation it came from. AI completion notices stay quiet while the window is in front of you.
  • Mail verification codes are set up right on that dashboard card: enter the address (servers for common providers such as QQ, 163, Gmail and Outlook are detected automatically), the port and an app password. New codes then appear on the card and in the bell, and clicking one copies it. The inbox is read-only — nothing is marked as read, no mail is sent or deleted, and bodies only pass through memory while the code is being extracted.
  • With many monitors you can search, tick several to enable, disable or delete in bulk, and drag them into order. Deleted ones go to the single app-wide recycle bin (Settings > History > Recycle Bin, linked from the monitor header) and come back with logs and configuration; entries older than 30 days are purged automatically. A one-hour maintenance window pauses checks and alerts.

11Schedules

Seven actions and six schedules cover everyday scripts and reminders.

  • Actions: open an application, open a folder, open a URL, run a command, send an HTTP request, run a script, or send a prompt to the AI (results append to the same conversation in run order).
  • Schedules: once, interval, daily, weekly, monthly (pick a day of month or the last day) and standard five-field cron.
  • Run one immediately from the list instead of waiting for the clock. Hitting ▶ on a row streams output into the run console below it — collapsible, with running state, duration and outcome visible, and each row also shows run count and average duration.
  • The list searches by name and filters to failed, enabled or disabled; each row shows how long until the next run. The run history filters to failures and exports to CSV.
  • Bot addresses are configured once under Settings → Robot Notifications; a task only decides whether to send and through which channel.
  • Deleted tasks go to the recycle bin. Restoring recalculates the next run from now, so a task whose time passed long ago doesn't fire the moment it comes back.

12Runtimes

Open Runtimes from the sidebar: groups on the left, versions and services on the right. aria2 lives in Dev tools too; install and start it before the downloader can work.

  • Install a version by picking it and clicking install; progress streams back live. Switch mirror when one is slow, or point at your own address; the install dialog also offers mirrors with acceleration, a custom source template, and a refresh of the version list.
  • Several versions of the same runtime coexist. Switching just moves PATH — nothing is uninstalled or overwritten. To make the terminal follow, set a version as the global default: its bin directory goes into the user PATH. When several versions' bin directories sit in PATH at once the app warns you (whichever wins depends on PATH order) and links straight to the PATH panel to clean up.
  • Service runtimes — Nginx, MySQL, Redis and the like — start, stop and restart from here. Configs can be edited in the app and reloaded on save.
  • Nginx, Apache and Caddy validate their config before starting; a syntax error stops there instead of breaking a live service.
  • Every service has live logs (last 8 KB) and a web console entry; the port overview shows which process holds which port.
  • Check Project reads the version declarations in a directory — .nvmrc, .tool-versions, go.mod, package.json, composer.json and more — compares them against what is installed and active, and switches to the missing version on the spot. If Everything returns nothing, the page has a self-test too.
  • Everything installs under %APPDATA%\QuickDock\runtime\: no registry writes, no system PATH changes, no admin rights.

13AI

Start under Settings → AI Assistant: pick a provider, fill in the base URL and key, pull the model list and choose one.

  • Once the profile exists, the chat page, the SSH sidebar, the clipboard's Ask AI and the notes window all share it. You configure it once, not four times.
  • The chat page has multiple sessions, automatic titles and modes (chat, explain code, translate, summarize, tutorial), and your own system prompt can be layered on top.
  • Formulas, diagrams and code blocks render. Diagrams, formulas and code blocks can be copied as images from the context menu, and html blocks open in a full-screen sandbox preview.
  • Switch to another page and the answer keeps generating; come back and it's where you left it.
  • Usage stats sit under Settings → AI Assistant: cost estimates for 7 days, 30 days and all time, split by model and entry point. They're linear estimates from built-in prices, not a bill — your provider's invoice is authoritative.
  • The assistant on the chat page can also do the work: read the project, edit files, run commands. Writes ask first — allow, remember or deny — and pending requests stay pinned above the input box, visible even after scrolling back. "Remember" covers one command family; per-tool overrides live under Settings → AI Assistant.
  • Files are snapshotted before they are edited, so any step can be reverted from the timeline, and the revert itself can be reverted. Works without git too.
  • Plan mode is read-only: it surveys the project and hands you a step-by-step plan before touching anything.
  • Project conventions go in AGENTS.md or .quickdock/rules/*.md instead of being repeated each time; type @ in the composer to pull in a file, a folder or a past conversation.
  • Keys are encrypted with Windows DPAPI; the front end never sees the ciphertext, and deleting a profile deletes it too.

14SSH

CtrlAltS opens a separate window that resizes and minimizes; switching windows doesn't drop the connection.

  • The host tree supports groups (folders), drag reordering, and environment tags: production, staging, test.
  • Authenticate with a password or a key (ed25519 and friends, passphrase supported). Older devices on ssh-rsa need the legacy switch turned on.
  • The first connection to a new machine asks you to confirm its fingerprint. Compare it against ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub on the server before trusting it. Trusted fingerprints are managed in known_hosts on the window's top bar, and a changed fingerprint raises an alert.
  • Several tabs on one host handshake once. Dropped connections reconnect on their own, and scrollback is kept. Reopen the window and last session's tabs come back.
  • A host can be tested for connectivity before you save the form, so you don't keep a config that never connects.
  • The SFTP panel browses remote directories, uploads and downloads, and multi-selects for batch download, move and delete; the path box takes a typed path to jump to. Saving writes a temp file and replaces atomically, comparing the remote hash first — if the file changed elsewhere you get a clear error instead of your edits silently overwriting it.
  • URLs printed in the terminal open on click (in your default browser, never by navigating the app window), output can be searched with jumps to each hit, and tabs can be dragged to reorder.
  • Broadcast input sends one command to several connected sessions at once. It sends one at a time and asks before each, so you don't type the same mistake on ten machines.
  • The host form's Advanced section holds the jump host, ProxyCommand, post-login commands and port forwards. ProxyCommand never goes through a shell — only %h %p %r are substituted — and stays off unless you tick it. OpenSSH config can be imported one way: it reads your file and never writes back.
  • Screen content sent to the AI sidebar is redacted first: PEM private key blocks, export KEY=... assignments, --token flags on the command line, credentials inside URLs, Bearer tokens and common vendor tokens are replaced, with the line count unchanged.
  • Run Command is one-shot: it runs and disconnects, keeping no session. On production hosts the risk is checked first, high-risk commands can only be filled in, CtrlEnter runs, and output is copyable.
  • Batch execution on a group lets you tick several machines, dry-run first (read-only — it lists the commands and their risks), then run, with output streamed back per host.
  • The AI sidebar on the right: select terminal output, right-click and ask. High-risk commands get a fill-in button only; you press Enter.

15Data & backup

Everything lives in ~/.quickdock by default; configuration is in %APPDATA%\QuickDock.

  • quickdock.db is the main database (workspaces, todos, notes, the clipboard index); images/ holds clipboard images, plugins/ plugins, logs/ logs.
  • Moving: change the storage location under Settings → Storage & Sync. The whole directory is packed and moved to the new drive, taking installed runtimes and environment variables with it, effective after a restart. Leave room on the target for the archive plus the unpacked copy.
  • Cloud sync: configure a WebDAV server on the same page for full JSON backups, keep several versions, restore in one click.
  • Snapshot: export everything to a JSON file and keep it somewhere. Importing overwrites current data — read the prompt first. A snapshot can be previewed to see how many items each module contains, created automatically every day or week, and older copies are pruned to a configurable maximum.
  • Uninstalling never deletes data; reinstalling picks it up again.

16Updates & fixes

On startup the app fetches a signed manifest and mentions new versions in settings.

  • Updates replace in place: download the new exe, verify the digest, then after a restart a helper backs up the old one and copies the new one over, rolling back on failure. No UAC, no installer.
  • Most update failures come from installing into a directory without write permission. Use the default path, or download and overwrite manually.
  • When something goes wrong, look under Settings → Logs: main logs by day, filterable by level, with JS and Go crash reports on the same page.
  • Log files can themselves be tailed: type logtail in the command palette, pick a file being written, and only new bytes are read every 500 ms.
  • If a hotkey does nothing, something else probably claimed it. Change it under Settings → Hotkey Settings; it re-registers immediately.
  • If a service won't start, check the validation output on its config page first, then the port overview to see whether another process holds the port.

17Downloader

The engine is aria2. Install it under Runtimes → Dev tools and start it first, then create tasks from the Downloader page.

  • Create a task: click New download, pick link, batch links, torrent file or Metalink, then fill in the address and destination. Magnet URIs go in as ordinary links.
  • Advanced options: the lower half of the dialog sets request headers, Referer, proxy, checksum, speed limits, seed ratio and queue position. Free space on the target drive is shown before saving, with a prompt when it runs low.
  • Watch progress: the list has status tabs, search, sorting and multi-select pause / resume / remove. Details opens a seven-tab dialog where URIs can be changed, files inside a torrent selected and options tuned for just that task.
  • BitTorrent and seeding: settings cover DHT, listen ports, trackers, encryption and seed ratio. These are read only when the engine starts, so stop and start it once from Runtimes after changing them. Inbound ports 6881–6980 need TCP/UDP allowed.
  • Remote engine: "Settings → Connection" in the downloads page can point at aria2 on another machine, with host, port and an optional secret. In remote mode files land on that host, so local disk checks and "open file location" are skipped.
  • Failures and completions: both reach the notification centre and can raise a desktop toast; failed tasks retry from the list, the context menu or the details dialog. A task that will not delete is usually a finished result — the page picks the right call and syncs the session, so there is no file to clean up by hand.
  • Check space before downloading: in the New dialog click "Check size" to learn the real file size and compare it with free space on the save drive; shortfalls are blocked. Remote mode only shows the size.
  • Separate folder per download: click "Browse" next to the folder, or use "url | folder" per line in batch mode; turn on per-file folders in the downloads page's "Settings → Automation" so downloads stop piling into one directory, and same-name links reuse the folder so resume hits the control file.
  • Protection on full disks: a download that fills the disk auto-pauses with a warning, and a stuck engine (write failures, RPC timeouts) restarts itself while the page shows "Restarting / Recovered", avoiding the restart storm.
  • Continue on another PC: copy the old PC's aria2.session plus the unfinished data file and its .aria2 control file, click "Import resume", pick the folder and session, fix names / urls / folders and submit — it resumes from the new PC's real path; magnets get no file name and expired signed URLs are swapped inline.

18Startup lock

For when someone borrows the machine for a minute, or you step away and would rather not sign out.

  • Set a startup password under Settings → Security, six characters minimum. A one-time recovery code is shown right after — it appears once, so write it down.
  • CtrlAltL locks immediately, and the tray menu offers Lock / Unlock depending on state. Once a password is set, every launch — auto-start at login included — asks for it first.
  • The lock covers the interface only. The main window and every detached window collapse to one unlock box, and panel hotkeys bring up the main window with a hint instead. Everything behind keeps running: monitors, scheduled tasks, mail codes, weather, the clipboard listener, SSH sessions, the MCP listener.
  • Clipboard history is hidden while locked, but ordinary copy and paste still works. Window tiling CtrlAltW and screenshots F1 stay allowed — neither reads this app's data.
  • It unlocks by itself once the password is fully typed; no Enter needed. Forgotten it? The recovery code clears the password and unlocks, then set a new one.
  • Settings → Security also offers "lock after N idle minutes", timed from the last keyboard / mouse input (watching a video still counts as idle); 0 or blank disables it. It has no effect until a password is set.
  • The password lives in local app_state and is deliberately left out of WebDAV backups. Restoring onto another machine leaves you with no password set, so set it again there.

19Password vault

Web logins, SSH and database credentials kept in one place. Not to be confused with the startup lock above: that one locks the interface, this one stores accounts.

  • The vault lives in the sidebar, list on the left and details on the right. A new entry takes a name, a type (web login / SSH / database / WebDAV / Git / API key / other), username, password, host or URL, tags and notes; anything important can be pinned. The list searches by name, username and host.
  • Entries are encrypted with AES-256-GCM before they touch the local database, and the key itself is random and wrapped by the system DPAPI. The vault stays on this machine only and is excluded from WebDAV backups — that is what keeps passwords from leaving, and the price is re-entering them on a new machine.
  • A copied password clears from the clipboard after 30 seconds. Locking with CtrlAltL also wipes the in-memory key; the first read after unlocking rebuilds it, so you are not asked again. New entries can generate a strong password in one click.
  • Web autofill needs the browser extension (Chrome / Edge, in browser-ext/ in the repo): turn on "browser integration" in the vault page, click "copy connection key" and paste it into the extension's settings. It stays valid until you switch the toggle off, which revokes the key and stops the local listener immediately.
  • The extension only offers entries that match the current domain — the whole vault never lands on someone else's screen — and filled values submit correctly on React / Vue sites. After login it offers to save, new passwords save automatically while changes still ask for confirmation, tracked per site so two different logins cannot overwrite each other.
  • SSH hosts no longer need a password up front: you get asked at connect time, the answer goes into the vault and the host is remembered. If the password changed, entering the new one overwrites both the host and the vault entry. The host form also has a "fill from vault" button.
  • Anything else that needs a password uses the same channel: the caller asks once, a prompt appears inside the app where you can pick a saved entry or type one and save it in passing. Concurrent requests queue up instead of stacking two boxes.

20Script tasks

Sidebar → Script tasks. This page owns the script itself — code, files, variables, dependencies, run history. Scheduled tasks only decide when it runs: pick the "run script" action and choose one.

  • One script is one directory: the entry file defaults by language (main.py / main.go / main.php, and you can override it) and side files such as config or requirements.txt sit next to it. The editor highlights syntax; CtrlS saves.
  • Languages ride on Runtimes: an installed Python / Node / Go / PHP is used, otherwise it falls back to the system PATH. Leave the interpreter blank to pick automatically. Dependencies install with one click, and a changed requirements file is flagged as possibly out of date.
  • Hitting Run streams the output below the editor — filter to errors only, search it, follow it. Finished runs land in History: replay one run, or full-text search every stored log. One instance per script by default; scraping jobs can go up to eight in parallel.
  • Two automatic triggers. HTTP trigger listens on loopback only; outside systems call POST /run/<script id> with a token, which can be rotated so the old URL dies immediately. Watch path runs once when a file or directory changes, and ten seconds of churn counts as one run.
  • Imported scripts need a one-time trust confirmation before the first manual run — a script runs as your user, exactly like typing the command in a terminal. An "allow MCP calls" switch sits on the page and stays off by default.
  • Scripts export to a zip and import back, and can be duplicated. Deleting one that scheduled tasks reference first tells you how many will break. Deleted script directories stay in the recycle area for 30 days.

21Knowledge base

Sidebar → Knowledge base. Register local documents, then search their contents and ask questions over them.

  • Add files or a whole folder. Nothing is copied — only the path is registered. Word, Excel, PDF and Markdown are among the text formats it can parse.
  • Every document carries an index state: queued, parsing, splitting, building the semantic index, ready. Failures, moved source files and a changed embedding model are called out separately; rebuild one document or all of them.
  • Three tabs on the right: Search (hybrid or keyword-only, three characters minimum), Ask (hands the matching chunks to the AI) and Chunks (how that document was cut up). Chunks are the only way to debug "why doesn't this match" — a table split apart or a PDF turned into noise defeats any search tuning.
  • Hits are labelled keyword match or semantic match, so you can see why one ranked first.
  • Several knowledge bases can coexist, one per project. Removing a document deletes only its index; the file on disk stays, and the confirmation says so.

22Bookmarks

Sidebar → Bookmarks. Import browser bookmarks and keep them tidy. Imported entries are ordinary web-type items living in the Bookmarks workspace, so opening and searching go through the same path as the resource tree.

  • Reads the bookmarks already stored by installed browsers — no export step. When a browser sits somewhere non-default, use "import from HTML file" with a file exported from its menu.
  • You see a preview before anything is written: how many were read, how many are new, how many duplicates and invalid URLs are skipped, and which collections the folders will become. Confirm, then it writes.
  • Three maintenance jobs: link check (runs the list and marks each status), find duplicates (merge by URL) and insights (which sites you save most). Missing site icons fill in with one click.
  • The list groups by collection and supports search on title and URL, drag ordering, per-entry rename and URL edits, copy URL and open in browser.
  • There is no read/unread state: these entries are things to use, not a read-later queue.

23Netdisk

Sidebar → Netdisk. By default it talks to the OpenList gateway installed on this machine — Baidu, Quark and friends are configured inside that gateway, and QuickDock behaves as a plain WebDAV client — but it can also connect to an OpenList you already run in Docker or on another machine.

  • First run offers "install OpenList" and starts it for you. Already have one? Choose "connect an existing OpenList" and fill in the address and account (an address like http://host:5244 gets /dav appended automatically).
  • Adding drives and scanning QR codes happen in the gateway's admin console; the app does not reimplement a login flow. With the gateway up but no storage added, the root is empty and the page says to add one there.
  • Browse, descend, upload, download, create folders, rename and delete. Downloads go through the system save dialog and progress is pushed into the page — it never picks a destination for you.
  • When the gateway is missing or stopped, the page offers install / start buttons instead of an empty list. Connected to an external gateway, it drops the install / start buttons and shows that address, its reachability and a way to disconnect.
  • Data goes straight between you and your own account; no third-party server in between.

24Git

Sidebar → Git. A window onto history and commits for local repos, not a full Git client.

  • Three columns: repos and branches on the left, worktree changes next, history and diff on the right. Every boundary drags — between the three columns, between history and the diff below it, and between the staged and unstaged panes; double-click resets.
  • The branch graph next to the history is laid out from each commit's parents rather than git's ASCII graph — connector-only lines in that output carry no hash, get dropped when parsing and leave broken stubs. Merges curve in, dots cover the lines they cross, and each lane keeps one colour. Rows are a single 28px line (subject, refs, author, date). A "current branch / all" switch above the list narrows it: the list is every ref mixed together, so switch to see only the branch you are on.
  • Frequent actions stay on the toolbar: fetch, pull, push, commit. Committing means staging files first (stage all is there), then CtrlEnter. The message can be generated from the current diff, and an amend folds it into the previous commit.
  • Rare actions that touch the disk live in the context menu: discard, ignore, stop tracking, tag, revert, create / rename / delete branches.
  • Conflicts get no resolution UI: it tells you plainly how to continue (resolve, then commit) or how to back out (git merge --abort). Interactive rebase, reset --hard and line-level staging are deliberately absent — those belong in a terminal.
  • The status bar always shows the branch, commits ahead / behind, how many files changed and the repository path.

25Plugins

Sidebar → Plugins. Plugins are small features you install and remove; they take effect immediately, no restart.

  • Two ways in: "install plugin" in the header picks a zip (or drop a zip onto the page), or browse the online marketplace. Marketplace sources are configurable, so an internal mirror works too.
  • A card shows state (running, ready, disabled, crashed), version, category and the permissions it declares. The button in its corner is the one action that applies right now — open its UI, enable it, or view its commands.
  • Hovering a card reveals power (enable / disable), kill, open, reinstall and uninstall in the top corner. Disabling only stops it and keeps its data; uninstalling offers to keep data too.
  • Plugins register commands and hotkeys: the card shows the first two, clicking opens the full list with trigger, hotkey and parameters. Those commands are searchable in the palette and callable by AI and MCP.
  • Before installing, the sensitive capabilities it declares (network, files, shell, clipboard, MCP tools and so on) are listed for confirmation; the line on the card is the same set, still reviewable later. Permissions are self-reported — the host cannot verify them.
  • Execution history at the bottom records success, duration and output for every command, with failures expandable. A crashed plugin backend shows as "crashed" on its card — hover to kill the process and reinstall; when the marketplace has a newer version, the sidebar entry carries an update badge.

26DeepSeek Harness

Sidebar → DeepSeek Harness is not a built-in page: it launches a separate window running DeepSeek's open-source agent framework, where tool calls, file edits and terminal runs happen.

  • The first click offers to set up the runtime: the app downloads Node, installs DSH and leaves you an "open DeepSeek" button — no terminal needed.
  • On first use you enter a DeepSeek API key in the DSH web UI. It binds 127.0.0.1 only and exposes no port to the outside.
  • Launching starts a process and waits for the port, so there is a visible delay: the sidebar entry spins and reads "starting…" during it. That is expected.
  • Settings → DeepSeek Harness shows status, start / stop, update checks, DSH plugin install and removal, batch plugin updates with a rollback to the previous set, and log export.
  • It is separate from the built-in AI assistant: that one is the in-app chat and delegation surface, DSH is the full external agent UI. It looks for Node already on the machine (including anything installed under Runtimes) and only downloads its own copy when none is found.
