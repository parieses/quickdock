STEP 01

安装与首次启动

系统要求

操作系统Windows 10 1809+ 或 Windows 11
运行时WebView2 Runtime（Windows 一般系统自带，缺了会提示下载）
磁盘约 50MB（不含后续安装的运行时，那些按需要下）
权限不需要管理员，不写注册表

两种装法，选一个

安装版quickdock-amd64-installer.exe — 推荐。默认落到 %LOCALAPPDATA%\Programs\快启坞，自动更新最省事
便携版quickdock-amd64.exe — 单文件直接跑。只要放在当前用户可写的目录（别放 Program Files），同样支持就地更新

Windows 安装步骤

  1. 下载 quickdock-amd64-installer.exe 并双击，一路默认不要改安装路径。
  2. 装完运行 QuickDock，任务栏托盘出现图标即启动成功。
  3. 按 Ctrl+Space 唤出主窗口，跟着首启引导页点几下（主题、开机自启、要不要示例数据）完成初始化。
别装到 C:\Program Files\...。那里写文件要过 UAC，就地替换更新会失败，只能每次手动下安装包覆盖。已经装错了？卸掉重装到用户目录即可，数据在 ~/.quickdock 不受影响。

STEP 04

工作空间与项目

QuickDock 用四层结构收纳一切资源。看着层级多，实际就一句话：按项目上下文分堆，再按关注点分页。

数据模型
Workspace（工作空间） — 顶级容器，隔离不同项目上下文
  └── Scene（场景） — 标签 / 图标 / 颜色，快速切换关注点
       └── Collection（集合） — 逻辑分组，可设打开策略与关联工具
            └── Item（项目） — 真正要打开的那个东西

项目支持 6 种类型

directory目录 — 用资源管理器或终端打开
file文件 — 用系统默认程序打开
url网页链接 — 用浏览器打开
command终端命令 — 在终端里执行
app应用程序 — 指定可执行文件路径
quicklink快速链接 — 带参数的快捷方式

从零建一套

  1. 侧边栏新建工作空间，比如「公司项目」「个人折腾」—— 它们彼此完全隔离。
  2. 在工作空间下建场景，比如「开发」「运维」「日常」，配个图标和颜色方便认。
  3. 场景里建集合，比如「前端仓库」「常用后台」「SQL 脚本」，集合可以设置打开策略（怎么开、用什么工具开）。
  4. 往集合里加项目：拖拽文件 / 文件夹进来最快，也可以手动新建填类型。

用起来顺手的几个点

  • 四个层级都支持拖拽排序，顺序按你的习惯排
  • 搜索基于 FTS5 全文索引，还支持拼音搜中文（敲 hj 能找到「环境」）
  • 命令面板会按最近使用 + 最常使用排序，越用越准
  • 场景的图标、颜色、标签随时改，改完立刻生效
STEP 05

命令面板

整个应用的核心入口。Ctrl+K 唤起，一个框搜遍全部资源，回车即执行 —— 手不用离开键盘。

  • 全局搜索：工作空间、场景、集合、项目统一索引，不用先切到对应页面
  • 排序会学习：最近使用 + 最常使用加权（frecency），常用项越排越前
  • 智能建档：粘贴一个 URL 进去，自动识别并存成项目，不用填表单
  • 多选批量：选中多项后一次性执行，比如批量打开一套开发环境的五个目录
  • 浮动窗口，Esc 或点外面就收起，不打断手上的活
最省事的用法：把每天开工要开的东西（仓库目录、Swagger、日志目录、数据库控制台）放进一个集合，之后 Ctrl+K 敲集合名 → 批量打开。
STEP 06

剪贴板历史

后台自动监听剪贴板，文本、图片、文件都记，Ctrl+` 随时翻旧账。

  • 常用条固定：把天天要粘的地址、Token 前缀钉住，不会被清理
  • 搜索：历史多了直接搜内容
  • 批量删除 / 按天自动清理：保留天数在设置里配，过期自动清
  • 浮动窗口失焦即隐藏；图片条目存在 ~/.quickdock/images/

想彻底不留痕迹：设置里关掉对应类型的记录（比如不记图片）。

STEP 07

截图与标注

F1 唤起全屏覆盖层，拖动框选、松手即定 —— 工具栏就地浮在选区下方，不用等第二个窗口弹出来。

  • 六种标注：矩形 / 椭圆 / 箭头 / 直线 / 文字 / 马赛克，配 9 种颜色、4 档线宽、6 档字号，带撤销重做
  • 画错了直接改：单击已画的图形即可选中并拖动位置，文字双击可重新编辑，内容清空即删除
  • 窗口吸附：鼠标滑过任意程序窗口即自动高亮并显示尺寸，单击直接选中整个窗口；按下 Ctrl 再移动，可下钻到按钮、输入框这一级
  • 贴图钉屏：把截图钉在桌面最上层，拖动移动、滚轮缩放、双击关闭，右键可复制或另存
  • 选框支持 8 点拖拽微调，尺寸实时显示；框选与调框时才出现十字对齐线

  • 浮动窗口失焦自动隐藏，下次唤起接着上次的笔记
  • 早期版本的「快捷笔记」会自动兼容成根级文档，老数据不丢
浮动笔记适合「临时抓一段」：报错信息、临时命令、别人发的一段配置。要长期保存的，进笔记管理页拖进对应文件夹。
STEP 09

待办与番茄专注

  • 双视图：列表看明细，看板按「待办 / 进行中 / 已完成」三列拖着走
  • 子任务：单层级 checklist，拆完打勾

番茄专注

在待办页选中一个任务启动倒计时，专注期间就盯着这一件事。倒计时结束弹系统通知，还可以配一个 Webhook 推送到手机（钉钉 / 企微 / 飞书等），离开电脑也收得到。

番茄钟和待办是绑在一起的：专注记录挂在具体任务上，回头看就知道这个任务花了几轮。
STEP 10

网站监控与通知

给自己负责的站点挂个探活，出问题第一时间知道，不用等别人来问。

能监测什么

状态码定时探测（GET / HEAD / POST），非预期码即告警
响应时间记录并出趋势图，可选 24h / 7d / 全部三个区间
SSL 证书到期前 N 天预警，天数自己定
内容匹配关键字或正则匹配页面内容，页面被篡改能发现
在线率统计可用性，配检测日志和状态翻转记录

通知怎么配

「Webhook 设置」里填渠道地址即可，支持 钉钉 / 企业微信 / 飞书 / Server酱 / PushPlus / Telegram。状态翻转（正常 ↔ 异常）时才推，不会一直刷屏。桌面端同时弹系统通知。

监控依托 QuickDock 主进程运行，关了应用就不探了。要 7×24 监控得让机器上的 QuickDock 保持运行（可以开开机自启）。

STEP 12

环境管理

把开发环境当成可装卸的模块：装、切、启停、改配置、看日志，全在一个页面。所有版本落在 ~/.quickdock/runtime/<name>/<version>/，不写注册表、不改系统 PATH，删掉 QuickDock 就一起没了。

安装一个运行时

  1. 左侧点运行时标签，自动拉取可安装版本列表。列表优先走 GitHub Releases API，失败自动用 HTML 解析兜底；国内源慢可以切镜像，换完点「刷新列表」重拉。
  2. 选版本 → 安装。下载 / 解压 / 安装全程异步，进度实时显示在界面上；多源回退 + 代理容错，一个源挂了自动换下一个。
  3. 装完可以再装别的版本，多版本共存，通过环境变量切换当前激活版本。

服务型运行时还能这么玩

启停重启一键启动 / 停止 / 重启，实时显示 PID、端口与健康状态
配置编辑直接改 Caddyfile / redis.conf / nginx.conf / traefik.yml / php.ini / frpc.toml 等
启动前校验Nginx / Caddy / Apache 等会先跑配置校验（nginx -t / caddy validate / apache -t），失败直接拦住不启动
日志查看弹窗实时滚动读取进程日志尾部 8KB
Web 控制台运行中直接打开：MinIO 9001 / Mailpit 8025 / Traefik 8080 / RabbitMQ 15672 / Nginx·Caddy 80
端口全景顶栏汇总所有服务的运行时 / 版本 / 端口 / 控制台入口

Ollama 是特例（单版本）

程序目录固定 runtime/ollama/，不带版本号、不做多版本并存 —— 单份约 1.4GB 且独占 11434 端口，多版本纯属浪费。有新版本时侧栏只提示不自动动，你点「更新」才走原地替换（下载 → 暂存 → 校验 → 替换），任何一步失败当前版本都不受影响，ollama.env 配置保留。

模型库默认与系统安装版共用 ~/.ollama/models，不用重下几十 GB。模型管理（列表 / 拉取 / 删除 / 查看已加载）都在界面里，走本地 REST API。卸载只删程序，绝不碰模型目录。

如果机器上已经装了官方 Ollama 且开机自启，QuickDock 会提示它会抢占 11434 端口，但不会自作主张禁用或卸载，自己决定怎么处理。
STEP 13

插件

「插件市场」里的官方插件一键安装 / 升级 / 卸载 / 启用禁用，装完还能给插件单独绑热键。

三种运行时

none纯前端，没有后端进程，最轻量
goja内嵌 JavaScript 沙箱，能跑逻辑不需要额外依赖
native独立子进程，能用系统级能力（如调用外部程序）

三者都通过 JSON-RPC 2.0 与宿主通信，能力面一致。插件装到 ~/.quickdock/plugins/<id>/。

安全模型

  • permissions.filesystem 声明目录 scope，读写越界直接拒绝
  • permissions.network 声明域名白名单，只放行列表里的域名
  • 插件不允许自己弹系统对话框 —— 文件 / 目录选择统一走宿主 API
  • 每个插件有独立的 KV 存储，互不干扰

写一个插件

宿主开放 29 个 Host API（日志、通知、剪贴板、对话框、KV 存储、文件读写、网络请求、Shell 打开、进程管理、窗口显隐，以及复用宿主 MCP 的 host.mcp.call）。最小骨架：

plugin.json
// none 运行时最小集：plugin.json + icon.svg + frontend/
{
  "id": "io.github.parieses.my-plugin",
  "name": "我的插件",
  "version": "0.0.1",
  "runtime": "none",
  "entry": "index", // 不要写扩展名
  "permissions": {
    "filesystem": ["~/Downloads"],
    "network": ["api.example.com"]
  }
}

完整开发文档与模板在 quickdock-plugins 仓库。

STEP 15

MCP 服务

QuickDock 自暴露一个 MCP（Model Context Protocol）服务，把本地能力开放给 AI 客户端 —— 让 AI 能真的操作你的环境，而不是只聊天。

接入步骤

  1. 确认 QuickDock 正在运行（MCP 随主进程，退出即失效）。
  2. 在你的 MCP 客户端里新增一个 HTTP 类型的 server，地址填 http://127.0.0.1:9230/mcp。
  3. 需要写操作（起停服务、改待办等）的，到「环境管理」页把高危等级打开。
客户端配置示例
{
  "mcpServers": {
    "quickdock": {
      "type": "http",
      "url": "http://127.0.0.1:9230/mcp"
    }
  }
}

能做什么

工具分三级权限门：只读（查环境、搜项目、看待办笔记、查端口、读日志）、低危写（起停服务、建待办、写笔记、复制剪贴板）、高危（杀进程、执行系统命令，默认关闭）。完整清单见下方 MCP 章节。

STEP 16

窗口管理

把窗口摆到该在的位置，别再拖着鼠标慢慢对边。两条路：单窗口贴屏用热键，整屏排版用浮层。

单窗口贴屏：点住窗口，按热键

  1. 鼠标点一下目标窗口，让它成为前台窗口。
  2. 按对应热键。比如 Ctrl+Alt+← 贴左半屏，Ctrl+Alt+3 塞到左下四分之一，Ctrl+Alt+Enter 最大化。

15 个动作的默认键见「快捷键」一节，也都能在「设置 → 窗口管理」里改。想要左窄右宽这类非常规分屏，去同一页调分屏比例（10%–90%，默认对半）。

热键用的是 Ctrl+Alt 而不是 Win+方向键——后者是 Windows 自带的贴靠，故意不跟它抢，两套可以并存。

整屏排版：一次点击排好一屏

  1. 点一下要当主角的那个窗口。
  2. 按 Ctrl+Alt+W 唤起排版浮层，浮层上是一排布局预览。
  3. 点布局里你希望主角待的那一块——当前窗口立刻进这一格，其余格子自动用本屏其他窗口依次填上，窗口不够的格子就空着。排完浮层自动收起。
9 种布局左右对半 / 左主右二 / 右主左二 / 上主下二 / 下主上二 / 四象限 / 三列 / 三行 / 九宫格
点卡片本身等于让主角进「主位第 1 格」，一次点击就是「按这个模板整理整屏」
排哪块屏鼠标所在的那块屏；单窗口热键另外支持把窗口在屏之间搬运
谁会被排只有和布局同在一块屏上的可见窗口参与自动填充，别屏的窗口不会被拉过来；最小化的窗口也不参与，免得一按热键弹出一排
典型用法：写代码时左边编辑器、右边浏览器，点一下编辑器再点「左右对半」的左格就位；开完一堆窗口后按 Ctrl+Alt+W 点「四象限」，一屏就齐了。浮层开着时再按一次 Ctrl+Alt+W 或按 Esc 即可收起。

STEP 18

更新与排错

更新流程

启动后自动拉取签名清单并验签 → 有新版本提示 → 你点「重启更新」→ helper 进程在主程序退出后备份旧文件、覆盖新文件（失败自动回滚）→ 重新拉起应用。不弹 UAC、不跑安装器。

常见问题

反复提示同一版本删除 ~/.quickdock/update-guard.json 强制重试。这个文件记录「已替换但版本号没变」的目标版本，连续 2 次未生效会自动忽略该版本
更新失败多半是装到了受 UAC 保护的目录（如 Program Files）。卸掉重装到用户目录
双击没反应单实例锁 —— 看托盘是不是已经有一个在跑了
装运行时卡住切换下载源（镜像）后点「刷新列表」重拉；下载失败会自动多源回退，也可以等它重试
想看报错主日志 ~/.quickdock/logs/quickdock-YYYY-MM-DD.log；更新替换日志 %TEMP%\wails-update-<pid>.log
反馈问题带日志去 GitHub Issues 提，复现步骤写清楚

FAQ

几个常被问到的问题

要管理员权限吗？会污染系统环境吗？
不要，也不会。所有运行时装到 ~/.quickdock/runtime/，不写注册表、不改系统 PATH、不申请提权。删掉 QuickDock，运行时一起没。
更新会丢数据吗？
不会。更新只替换主程序文件，~/.quickdock 下的数据库、插件、运行时目录全部保留。跨版本配置变化由数据库迁移逻辑处理。
数据存在哪？会上云吗？
全在本地 SQLite。只有你主动配置 WebDAV 同步时才会上传备份；AI 助手的 API Key 在 Windows 下用 DPAPI 加密存储，前端不接触密文。
插件能做什么？安全吗？
插件声明 permissions.filesystem 目录 scope 和 permissions.network 域名白名单，宿主逐次校验，越权直接拒绝。插件不能弹系统对话框，文件选择统一走宿主 API。
支持 Linux 吗？
引擎层已按 _windows / _darwin / _unix 拆文件，但目前官方只发 Windows 产物，Linux 尚未纳入发布流程。截图与贴图是 Windows 原生实现，其他平台暂不可用。
怎么用 AI 控制 QuickDock？
在任意 MCP 客户端（如 WorkBuddy）里把 http://127.0.0.1:9230/mcp 加为 HTTP 类型 server，即可调用这些工具。高危工具需要你先在环境管理页手动开启。
