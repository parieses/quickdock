# prices.json — 模型价目快照

`services/ai/ai_pricing_snapshot.go` 用 `//go:embed` 把这份文件编译进程序，用来补
内置价目表（`ai_pricing.go` 的 `aiPriceRules`）的覆盖缺口。

内置表按模型名**前缀**匹配，只覆盖少数常用模型；而实际请求记录的模型名常带渠道
前缀（如 `opencode-go/deepseek-v4.1-flash`），前缀一条都对不上，整批调用会变成
「未计价」、花费显示 0。这份快照按「渠道 / 模型」精确匹配，正好补上。

## 字段

```json
{
  "rate": 6.679299,
  "at": "2026-11-24",
  "p": {
    "<provider>": {
      "<model>": [input, output, cache_read]
    }
  }
}
```

| 字段 | 说明 |
|---|---|
| `rate` | 生成快照时的 USD→CNY 汇率，也是**全表唯一的折算依据**（手写表里的美元价同样按它） |
| `at` | 快照日期（汇率对应的日期） |
| `p` | `provider → model → [输入, 输出, 缓存命中输入]` |
| 单价 | **美元 / 百万 token**，写 USD 原值，不预先折算；折算发生在 `estimateCost` 一处 |
| `cache_read` | 缓存读取价；`0` 表示该渠道未单独定价，按输入价计 |

模型名一律小写；查表时也是小写 + 精确匹配，不做模糊/前缀匹配——同一模型在不同
渠道的价差能到十倍，拿别的渠道价顶替算出来的钱没有意义。

## 更新

只有一个文件要改，改完重新构建即可（`wails3 build`）：

1. 改 `p` 里的单价（USD / 百万 token），或新增 `provider/model`。
2. 同时更新 `rate` 与 `at`——汇率变了单价折算就变了。
3. 删掉下线的模型是安全的：历史 `ai_usage` 里若还有它的记录，会退回内置表或标为
   「未计价」，不会算错钱。

## 为什么不读运行时文件

价格本来可以每次启动去抓，但那样程序就要依赖外部工具的运行目录或在线接口：
换机器、卸载、断网、对方改格式，都会让花费莫名其妙变 0 或变错。内嵌快照的代价
只是「价格不会自己变」，而这个数字本来就该由人确认后再改。
